# Architecture

Traffic Phase is a Python application. FastAPI provides the API and serves a
browser player generated by Python. Browser controls use a small amount of
JavaScript; generated recordings and HTML reports are runtime output.

## Offline

`app/core/intersection_project.py` inventories JSON/ZIP inputs, separates source
clocks and observation sessions, runs trajectory-based discovery, and persists
an intersection model. `app/core/recovery/` extracts movement permissions and
recurring structure. `observed_topology.py` estimates observed approaches.

The model contains candidate configurations, phase counts, duration statistics,
recurring regimes and provenance. Geometry and physical sections are hypotheses:
an unused approach or an additional arrow cannot always be identified from cars.
The normal intersection-project workflow does not require a site profile, video,
manual lamp labels or a user-specified K.

## Online

`app/core/intersection_online.py` consumes current detections against the saved
offline structure. It retains bounded track histories, detects causal movement
events and estimates phase and age. `intersection_emissions.py` compares movement
marks across regimes. K and hardware are not rediscovered online.

`intersection_online_store.py` journals packets and issued responses for replay
and restart recovery. The same panel displays offline and online cars/signals.

`intersection_engine.py` selects v8 for fresh offline models with queue geometry.
The selected implementation reuses the joint timing, front-release, waiting and
change-point modules under `app/experimental/`; unrelated experiments remain
disabled. An unexpected completed queue-front interval creates a competing
duration program; observations select it while the ordinary program remains.
The number of hypotheses is bounded at 16. Missing traffic is not negative GREEN
evidence, and waiting on an approach with an arrow does not identify the main
section's color. Offline discovery learns queue geometry from raw trajectories.

Old models without references use v7. Each journal records its engine version;
recovery uses that exact version and verifies previously issued responses.
Transactional copies retain their own observation callbacks. Live output and
retrospective history remain distinct. V8 improves aggregate measurements but
has not passed the strict all-color/false-GREEN regression gate; see the
[acceptance record](../results/causal_v8.md).

## Repository layout

| Directory | Contents |
|---|---|
| `app/` | Python application, inference, API and isolated research modules |
| `scripts/` | Launch helpers, CLI, synthetic generators and evaluation tools |
| `tests/` | Unit/API tests, synthetic checks and optional saved-run audits |
| `config/` | Compatibility resources for explicit legacy diagnostic tools |
| `docs/` | Architecture, input contract and current delivery status |
| `results/` | Compact accuracy summary, coverage and provenance |

`config/known_intersections.json`, timing profiles and learned profiles are read
by the explicit diagnostic/learned-profile endpoints. They are retained to keep
those tools functional; they are not ground truth for the automatic product path.

Private archives, generated HTML/players, snapshots, frames, logs and old research
reports stay local under ignored `data/`, `logs/`, `.web_runtime/`, `evidence/`,
`benchmarks/` and `diagnostics/`. Ignoring these does not delete existing files.
Saved-run audit tests are marked `local_evidence` and skip in a clean clone;
algorithm and API tests run without those artifacts.
