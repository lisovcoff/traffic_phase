# Trajectory recovery v1 — проверка и запуск, 19.10.2026

Улучшенный алгоритм подключён к обычному `/visualization/analyze`, веб-пакетному
анализу и CLI. Вход: JSON или ZIP с траекториями; видео и разметка не нужны для
прогноза. Прежний алгоритм доступен явно как `legacy_v9`; обученный режим остаётся
отдельным и получает K из прежнего профиля. `main` не менялся.

Запуск из `audit_checkout`: `START_WEB.cmd`, затем
<http://127.0.0.1:8017/visualization>. Работающий старый сервер нужно перезапустить.
Launcher предпочитает имеющийся проверенный Python3.12; явный
`TRAFFIC_PHASE_PYTHON` имеет приоритет.

Без запуска сервера можно открыть
[`report_v2.html`](../evidence/accuracy_recovery_20261019/report_v2.html): там готовые
интерактивные просмотры трёх настоящих записей, графики всех96 сценариев,
траекторные ZIP без истинных фаз и перечень219 реальных источников.

## Что исправлено

- События разрешённого движения выбираются отдельно по каждой машине: остановка
  и последующее начало движения, иначе пригодный прокси пересечения. Наличие
  остановившихся машин одного манёвра больше не отбрасывает остальные машины.
- Период определяется по свидетельствам движения, а не только прибытиям.
  Отдельная коррекция по первым машинам очередей убирает дрейф центра разъезда.
- Выбор K различает новые разрешённые манёвры и изменение интенсивности тех же
  потоков; неинформативные тихие компоненты не становятся самостоятельной фазой.
  Число фаз не выбирается по названию файла или видео.
- Там, где в данных действительно наблюдаются нулевые скорости, учитывается
  интервал между последней остановкой и началом подтверждённого движения.
  Это начало движения автомобиля, а не непосредственно наблюдённый GREEN.
- При устойчивом периоде границы уточняются локальными событиями с фиксированной
  регуляризацией0,75с. При неустойчивом цикле используется исходная локальная
  история; это не возобновление экспериментального декодера2D.1.
- Обрабатывается весь выбранный сеанс, включая длинные записи. Источники и
  разделённые сеансы не объединяются. Производственный backend не подменяет
  глобальные функции и не читает экспериментальные модули.

Жёлтый и красно-жёлтый используют общий ранее проверенный модуль переходов.
Для Свердловского сохранена подтверждённая схема: N/E с дополнительной секцией,
W/S без неё. Профиль оборудования влияет на физическую проекцию, а не является
независимым доказательством K. Автоматическая видеопоправка отключена.

## Измеренный результат

Алгоритм/параметры зафиксированы в `candidate_freeze_01.json` до оценки24 новых
случайных сценариев и свежего фрагмента видео.72 прежних случая — разработка.
Подсчёт ошибки охватывает полную запись, включая UNKNOWN и непокрытые интервалы.

| Данные | K до → сейчас | Ошибка истории фаз | Ошибка цветов основных голов | Границы ±2с, найдено/истина |

|72 сложных случая,62 часа, разработка|13/72 →68/72|42,13% →4,01%|36,40% →6,79%|1661/6474 →6117/6474|

Точность границ среди всех прогнозов:6117/6556 на разработке и919/974 на новом
контроле. Средняя по случаям правильность основного назначения манёвров:
97,12%/100%; полного состава с учётом shared movements:96,34%/100%.
Физические цвета здесь вычислены автоматической проекцией приложения, не
диагностической проекцией «каждый манёвр — одна голова». Это синтетические
основные головы; доказательства реальной аппаратной топологии из этого нет.

Новый контроль содержит11 132 машины и5 016 115 детекций. Прежние72 случая:
101 960 машин и54 694 888 детекций. Есть редкий и насыщенный поток, пачки машин,
уступание, ненулевая ошибка датчика стоящей машины, перекрытия, смена периода,
четырёхчасовые записи, shared movements и развороты.24 новых случая — другие
случайные реализации того же симулятора, не новые реальные перекрёстки.

Оставшиеся ошибки K на разработке: `k2_sparse_0` (3 вместо2), `k2_sparse_1`
(4 вместо2), `k3_starved` (2 вместо3), `k5_starved` (4 вместо5). Они не исключены
из итогов. Различные планы контроллера с одинаковыми наблюдаемыми потоками
сохранены в прежнем отчёте как контрпример однозначного восстановления.

## Воспроизведение

```powershell
python -m scripts.v9_spatial_visualizer input.zip --source-member exact.json --output viewer.html
python -m scripts.archive_batch run input.zip --out new_batch
python -m scripts.verify_recovery_release --workers 3
python -m scripts.check_recovery_application --key real_0091
python -m scripts.qa_recovery_release --evidence evidence/accuracy_recovery_20261019 --output new_browser_check
```

Для повторной проверки нужны сохранённые локальные caches и исходные материалы;
команды генерации evidence требуют нового пути, существующие результаты не
перезаписываются. `check_recovery_application` создаёт новую папку, поэтому
готовую проверку нельзя молча запускать поверх старой. Для обычного прогноза
эти caches, видео, разметка и evidence не требуются.

Приложение работает с улучшенной измеренной точностью. Заявление «максимально
возможная точность для любой дороги» не доказано. Полная приёмка локальных
продлений/смены режима2D.1 остаётся FAIL/default-off, `main` сохранён.
