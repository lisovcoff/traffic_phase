## Что работает

`START_WEB.cmd` → http://127.0.0.1:8017/visualization. Уже работающий сервер
нужно перезапустить для загрузки нового кода. Внешний сервер этой проверкой не
запускался; браузерные запросы направлялись в TestClient, Edge работал отдельно
от пользовательского профиля.

В одной панели: JSON/ZIP → «Анализировать» → прогресс → список всех рассчитанных
записей → плеер с машинами, сигналами, перемоткой, скоростью и выбором точного
времени по Екатеринбургу. Выбор записи влияет только на просмотр: анализ уже
выполнен для всего архива. Фазы/схему оператор не задаёт. Именные профили и
видео/метки в новом пути не используются.

Модель и отдельные результаты сеансов сохраняются в
`logs/intersection_projects/<id>/`. Оригинальные файлы не изменяются. Артефакт
содержит SHA256, инвентарь файлов, отдельные часы/идентификаторы сеансов,
наблюдаемые подходы, каталог повторяющихся конфигураций, вероятности движений,
статистику длительностей и наблюдённых переходов. Повторное открытие модели и
визуализация не запускают подбор фаз заново. Модель можно скачать из панели;
скачанный JSON описывает структуру, но сам по себе пока не является переносным
пакетом исходников и плееров.

Пределы нового пути:16GiB вход,64GiB суммарных распакованных JSON,4GiB отдельного
JSON,512 источников/сеансов согласно проверке инвентаря. Источники анализируются
последовательно в отдельном процессе. Это допустимые пределы, а не измеренный
SLA для максимального размера. Ошибки не скрываются: неполный результат PARTIAL
содержит конкретные причины. Небольшие корректные JSON с метаданными пропускаются
явно; повреждённые JSON дают ошибку. Сервер остаётся доступным при вычислениях.

## Проверки и самокоррекция

Материалы: `evidence/intersection_project_20261019/`.

- `real_archive_v2/receipt.json`: полный оригинальный ZIP Свердловского,
  180555021байт,3JSON/3сеанса,183.64с; максимальный измеренный ответ health16мс.
  Все три записи дают одну группу с K=3 рабочих конфигураций. В третьей записи
  остаются4 латентных состояния: повтор конфигурации не считается новым цветовым
  состоянием и не исчезает из истории. Предсказанный исходный результат сохранён.
- `browser_v3/receipt.json`: реальная модель, повторное открытие, плеер,
  выбор даты/времени, мобильная ширина390px, настоящий upload переименованного
  синтетического ZIP через кнопку; K=2, без ручного профиля; ошибок JS нет.
- `enthusiasts_archive/receipt.json`: все6JSON/6сеансов второго оригинального
  архива,207.89с, без ошибок. Каталог предлагает3группы с K=2/3/2; это разные
  гипотезы наблюдённых конфигураций, **не доказательство трёх реальных программ**.
- `t_geometry_v5/receipt.json`: Т-образный пример из очередей/кинематики,
  331траектория/92314детекций; три подхода N/S/E, K=2, отсутствует фиктивный W,
  основной E управляется наблюдаемым E→N. Ground truth записан отдельно и не
  передаётся приложению. Это разработочный пример геометрии/интеграции,
  **не независимая оценка точности**. Проверки поворота схемы покрывают все4
  ориентации; отсутствие потока в одном файле не удаляет подход из всего архива.

Сохранены и неудачные промежуточные результаты. Сначала каталог считал латентное
K=4 отдельным режимом: исправлено сравнение рабочих конфигураций. Первая
браузерная проверка нашла Windows-конфликт одновременного создания кэша:
исправлены уникальные временные имена и выдача готовой страницы при недоступном
кэше. Первый общий pytest нашёл регрессию старой learned-страницы: возвращён её
отдельный шаблон. Второй нашёл устаревшую текстовую проверку JS; проверка обновлена
с сохранением всех численных assertions. Начальный Т-пример прошёл геометрию,
но слил2 фазы в1: `t_geometry/receipt.json` прямо содержит K=1. Это структурный
FAIL, несмотря на его геометрический PASS. Новая ограниченная T-проекция
сохраняет2 состояния; тест теперь требует их и смены основного E.
В `t_geometry_v3/` сохранена неудачная проверка QA, ошибочно требовавшая ровно
два цвета при уже включённых жёлтом/красно-жёлтом. Финальная проверка требует
наличия GREEN и RED, сохраняя переходные состояния.

Точная итоговая команда/результат pytest и хеши журналов находятся в
`checks/full_pytest_v3*`. Ранее неудачные прогоны также сохранены.
Итог: **1449 PASS**,5 прежних предупреждений; затем30 целевых PASS после правки
подписи наблюдаемых подходов. `START_WEB.cmd --check` PASS; `git diff --check` PASS.
Все6 плееров Энтузиастов также открыты через API: `enthusiasts_viewers/receipt.json`;
в каждом доступны оценённые сигналы, правильный source scope и сохранённый K,
без нового подбора и известных профилей.
То же проверено для всех3 плееров Свердловского: `sverdlovsky_viewers/receipt.json`.
`t_structure/receipt.json`: **8/8** разработочных случаев — K2 иK3 в каждой из4
ориентаций Т-перекрёстка. Протокол и все исходные случаи/GT сохранены до запуска
подбора; правильны наблюдаемые подходы и число рабочих состояний. Параметры
по результатам не менялись. Это регрессионная проверка структуры, не новый
независимый holdout и не измерение реальной точности ламп.

## Что остаётся

1. Полная приёмка переменных длительностей/продлений/смены и возврата режимов.
   Каталог сейчас группирует наблюдаемые конфигурации эвристически; дни недели
   сохранены как признаки, календарная программа не объявляется доказанной.
2. Причинный online на этом сохранённом артефакте: секундные пакеты машин,
   фиксированная офлайн-структура, состояние/история/восстановление и визуализация.
   Старые online endpoints пока не являются этим контрактом.
3. Дополнительные секции и геометрия остаются гипотезами. Т-проекция использует
   селективность наблюдаемых движений; по траекториям нельзя доказать устройство
   скрытой головы. Необозреваемый пустой подход может отсутствовать в наблюдениях.
   Идентичность всех файлов одному перекрёстку заявляется при загрузке, ещё не
   сертифицируется автоматической проверкой физической геометрии.
4. Новые независимые проверки точности/задержки, длительный online replay,
   эксплуатационные сбои и комплект сдачи. Готовность UI и PASS unit tests
   не заменяют эти проверки.
   Возобновление незаконченного задания после аварии процесса ещё не реализовано;
   уже законченная сохранённая модель восстанавливается.

Основной численный trajectory_recovery_v1 не перенастраивался. Прежние реальные
метрики и ограничения из ACCURACY_RECOVERY_RESULTS_20261019.md сохранены;
пауза2D.1 FAIL/default-off остаётся. Новая T-проекция — отдельная гипотеза
оборудования, её точность на реальных T-перекрёстках ещё не установлена.
