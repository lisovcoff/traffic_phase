# Проверка алгоритма по manual_marks, 18.10.2026

Новое прямое задание пользователя разрешает реальные прогоны и исправление
алгоритма по данным в `../data/ручная разметка/`. Основа9cca954; main не менять,
исходные данные, предыдущие predictions и отрицательные результаты сохранить.
Это проверка/разработка по знакомым записям, не новый независимый holdout.

Подтверждённая пользователем схема Ленина–Свердловского:4 основных светофора,
W иS без допсекций, N иE по одной допсекции. В ранее переданном review17
описаны движения допсекций N→E иE→N и группы:
EW={E→W,W→E}; TURN={N→S,N→E,E→N}; NS={N→S,S→N}.
Эту внешнюю схему можно передавать как известное ограничение; нельзя выдавать
её за автоматически обнаруженную по траекториям топологию или распространять
на другие перекрёстки. Допсекция не означает дополнительную логическую фазу.

Вход проверки: три парных JSON/manual_marks с префиксами17_2025_2_19_10,
19_2025_2_24_16 и6_2025_2_14_20. Сначала один свежий baseline на каждом полном
trajectory JSON, dt=1, seed0, штатный K-search2..6, без marks_path и иной
передачи меток в inference. Лимит180с на файл, максимум3 запуска/540с;
недоступные результаты и таймауты не заменять удачными записями.
Prediction/hash сохранять до оценки. Сравнить с прежними cached predictions.

Сохраняется прежняя оценка: абсолютные границы один к одному, ±2с, без
подгонки сдвига, исключая первый и последний цензурированные marks.
Отдельно новая заявленная пользователем задержка ручного нажатия0..3с:
фактическое переключение совместимо с интервалом[mark−3000,mark]мс.
Не превращать это в симметричный допуск±3с и не сдвигать predictions по truth.
Публиковать весь знаменатель, пропуски, лишние границы и signed errors.
Состав фаз и топологию оценивать отдельно от временных границ.

старый evaluator и не подбирать параметры после просмотра его результата.
Если дальнейшая модель потребуется, записать новый отдельный план и причины.

заданный пользователем K/каталог нельзя засчитать как автоматически найденный.
