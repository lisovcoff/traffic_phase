# Ручная разметка: первый шаг плана

Запуск из корня проекта: **START_ANNOTATION.cmd**. Либо из `audit_checkout`:

```powershell
py -3 -m scripts.run_annotation
```

Откроется http://127.0.0.1:8011/annotation. JSON обрабатывает локальный Python,
выбранное видео остаётся в браузере. Интернет не нужен. Если сервер уже запущен,
launcher открывает его повторно. Другой порт: `--port 8012`. Роут `/annotation`
также добавлен в существующий FastAPI app; обычный inference/default не изменён.

## Первое задание разметчику

1. Откройте trajectory JSON (архив сначала распакуйте), введите имя/псевдоним.
   Начните с окна **0–180 секунд**. Файл читается потоково для временной базы и
   SHA256, но браузер получает только точки выбранного окна. Порядок треков не
   влияет на origin. Отображается дата/время UTC+5 и секунды от начала записи.
2. В «Что известно о перекрёстке» укажите название, состав групп, общие движения,
   реальные допсекции, откуда и когда вам это известно. Например: «Группа 1 —
   N→S, S→N». Номера групп — ваши обозначения, не mapping модели.
3. Нажмите «Пуск». Цвет машины означает movement, а не светофор. Клик по машине
   или список выбирает трек. Показаны точки до/после курсора, sampling gap и raw
   speed с UNKNOWN units. Геометрия — исходные image coordinates, есть flip Y;
   стоп-линии не выдумываются.
4. Используйте «Старт»/«Остановка» либо «Фаза 1/2/3»/свою подпись. Кнопка ставит
   паузу и подготавливает метку. Уточните интервал, затем нажмите «Добавить».
   Для события автомобиля требуется выбранный трек. Uncertainty можно оставить
   UNKNOWN. Относительное замедление само по себе не является остановкой.
5. Основание «Траектории + знание перекрёстка» сохраняет экспертную реконструкцию.
   Она полезна, но время движения автомобиля не становится точным временем
   лампы. Для неясных мест используйте широкий интервал, UNKNOWN, неполную
   видимость и комментарий, а не вынужденную точную границу.
6. «Скачать разметку JSON» создаст `имя_записи_review.json`. Пришлите его с именем
   исходной записи. В экспорт входят source SHA256, временная база, track ID/
   fingerprint, источник, метки и uncertainty; все траектории не копируются.

Для начала достаточно непрерывного окна в несколько циклов на одном перекрёстке:
группы, старты/остановки, предполагаемые границы и неясные места. Не отбирайте
только удобные события или ошибки модели. Предсказаний модели здесь нет.
Для следующего участка измените начало окна (например, 180с) и снова откройте
тот же JSON. Все метки сохраняются в общей временной системе по source SHA256.

## Сохранение

Черновик сохраняется в localStorage этого браузера по SHA256. Это удобство, не
резервная копия: регулярно скачивайте JSON. Для продолжения откройте исходный
trajectory JSON, затем импортируйте `_review.json`. Другой hash/временная база
отклоняются. Метки разных окон не удаляются. «К метке» вне текущего окна
подготовит нужное начало и предложит повторно открыть JSON. Импорт заменяет
набор меток, поэтому перед импортом сохраните текущую работу.

calibration_candidate/validation_candidate — заявка на роль, не сертификат
независимости; нужны проверки split. Знакомые записи остаются development.

## Видео

Выберите локальный MP4, включая предоставленный
`len_sverdl 2025-02-27T10_00_00_2025-02-27T12_00_00.mp4`.
Дата/интервал JSON должны действительно соответствовать видео: одного названия
перекрёстка недостаточно. На курсоре JSON задайте соответствующую секунду видео
и нажмите «Связать…». «Показать этот момент видео» выполняет seek. Это ручной
anchor, не проверка clock synchronization; автоматического видеоанализа нет.

Только когда сигнал виден или указан в независимом журнале, выбирайте
«Наблюдаемый сигнал» и внешний source/reference. GREEN/RED/YELLOW/OFF/UNKNOWN
сохраняются как review claims, `independently_verified=false`, до отдельной
проверки. `operator_documented` synchronization требует основания и uncertainty.
Vehicle timing uncertainty отделяется от неизвестной event-to-signal задержки.
Геометрия и units остаются UNKNOWN без подтверждающего источника.

## Лимиты и проверки

Один JSON-массив: до 256 MiB, 6000 исходных записей, 300000 отображаемых точек,
окно до 1800с; бюджет подготовки 30с на два streaming-прохода. Превышение —
явная ошибка, не частичная «полная» история. Выберите меньший сеанс/окно.
Interpolation gap влияет только на отображение; при больших gaps машина не
интерполируется. Временной extent не равен camera coverage. Нет fitting, K search,
HSMM, phase predictions или оценки реальной lamp accuracy.

18 unit/route tests прошли. В браузере проверены выбор/seek, экспорт/импорт,
mismatch hash, восстановление черновика и запрет trajectory→observed lamp.
Загружен префикс 20 реальных треков (1.42 MB), без фазовой разметки. Полный
175 MB JSON и весь корпус не прогонялись. Демо синтетическое. UI проверен
установленным Chrome headless с отдельным тестовым профилем после недоступности
Browser/Computer Use helpers. Логи/скриншоты: evidence/annotation_step1_20261015/.
Синхронизация реального видео и независимая truth ещё не проверялись.
