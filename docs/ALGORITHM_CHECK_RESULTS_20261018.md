## Что реализовано, но оставлено экспериментальным

`select_permission_events_per_track` сохраняет наблюдение каждой машины:
предпочитает её собственный поддержанный RELEASE, иначе её допустимый
CROSSING_PROXY. Источник/fingerprint/movement разделяют машины и записи;
порядок детерминирован, дубликаты и второе событие той же машины не дают
дополнительного вклада. Неопределённость наблюдений и фильтры качества сохранены.
Шесть тестов проверяют потерю50 машин из-за одного RELEASE, дубликаты,
непригодные события, источники, качество и перестановки входного порядка.

Старый default не заменён этим вариантом: дополнительные события проезда
меняют распределение времён наблюдений и в данной модели ухудшили результаты.
Причина ухудшения ещё не установлена; возврат данных сам по себе не
доказывает корректность смешивания RELEASE/CROSSING_PROXY в одной эмиссии.
Для дальнейшего развития нужна проверка модели разных типов наблюдений и
их неизвестной связи с реальным переключением, а не ручная поправка времени.

Протоколы: PER_TRACK_PERMISSION_PROTOCOL_20261018.md,
ISOLATED_PHASE_CHECK_PROTOCOL_20261018.md, OBSERVATION_PHASE_CHECK_PROTOCOL_20261018.md.
Последний протокол завершает раунд; дальнейших гипотез по этим оценкам не
подбирали. Параметр0.15, предложенный Gemini, не применялся.
