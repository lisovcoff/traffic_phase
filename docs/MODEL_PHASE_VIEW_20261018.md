# Цветная оценка движений в пространственном просмотре

Исправлено по сообщению пользователя 18.10.2026: и реальный архив, и предложенный
синтетический пример показывали только «?» на всех светофорах. Причина — основной
вид рисовал неизвестные физические лампы, скрывая полезные вычисленные
характеристики движений. Это был не сбой загрузки JSON.

В обычном пространственном просмотре теперь по умолчанию выбран режим
**«Движения по фазам — оценка»**. На схеме вместо неподтверждённых трёхсекционных
светофоров показаны отдельные индикаторы движений каждого подхода. Справа видны
те же движения, выбранная фаза выделена рамкой, воспроизведение и перемотка
обновляют все элементы согласованно.

Цвет описывает **относительную характеристику событий движения в выбранной
фазе**, уже вычисленную V9:

- Зелёный: значение не ниже 70% максимума этого движения по фазам.
- Серый: значение ниже этой границы.
- Жёлтый: доступные характеристики одинаковы во всех фазах, фазовой
  избирательности нет. Это не жёлтый сигнал светофора.
- Нет оценки/«?»: фаза неизвестна, отсутствует характеристика для неё или нет
  ненулевой характеристики движения. Пробелы истории не заполняются периодом.

Абсолютный порог occupancy не применяется к цветам этого вида: при редких
событиях он делал даже различающиеся характеристики синтетического примера
целиком серыми. Это нормировка отображения, не изменение обучения, K, истории,
event selection или физического разрешения движения. Значения и правило цвета
доступны в подсказке строки. Shared movement может подсвечиваться в нескольких
фазах; отсутствующая характеристика не заменяется нулём.

Переключатель **«Отображение → Физические лампы»** возвращает проверяемый
физический слой. Его состояния по обычным траекториям остаются UNKNOWN;
экспорты и общий state contract не заменяют их цветами событий. Жёлтые,
красные и дополнительные аппаратные секции из активности не выдумываются.

## Как увидеть исправление

Сохранённый результат пользователя и синтетический пример перерисованы из
существующих `logs/.../v9_result.json` и данных прежнего HTML. Исходные файлы
побайтно сохранены; новых real extraction, phase fitting или calibration нет.
Контрольные суммы и число отображаемых траекторий записаны в
`evidence/model_phase_view_20261018/rebuild_verified.json`.

Готовый новый синтетический HTML:
`evidence/model_phase_view_20261018/synthetic_model.html`.
Полный отчёт реального архива сохранён отдельно в соседней с репозиторием
папке `deliverables/traffic_phase_real_model_20261018.html`.

Уже открытая страница содержит старый самодостаточный HTML и автоматически
не обновится. В окне сервера нажать Ctrl+C, снова запустить `START_WEB.cmd`,
обновить страницу и выполнить анализ. Для просмотра уже перерисованного
реального отчёта повторный анализ не нужен: открыть его HTML в Chrome/Edge.
