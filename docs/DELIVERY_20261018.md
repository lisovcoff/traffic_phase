# Комплект программы traffic_phase, 18.10.2026

Назначение: «Разработка модуля вычисления фазы светофора в условиях отсутствия
прямой видимости по косвенным параметрам транспортных потоков».
Уточнение заказчика: свидетельство о государственной регистрации программы для
ЭВМ; отдельного требования к процессорам ARM нет. Этот комплект содержит код и
результаты технической проверки, не является поданной регистрационной заявкой.

Приложение выполняет JSON/ZIP → выделение движений → оценку числа, состава и
порядка логических фаз → периодическое расписание и диагностику → HTML.
Оценка логической фазы отделена от физического состояния секций. Неоднозначные
физические состояния остаются UNKNOWN. Экспериментальная локальная история
отключена по умолчанию; её приёмка 2D.1 по-прежнему FAIL.

## Запуск на Windows

1. Установить Python 3.12 и распаковать комплект в отдельную папку.
2. Запустить `INSTALL.cmd`: создаётся `.venv`, устанавливаются зависимости из
   `requirements-tested-py312.txt`, проверяется импорт приложения. Это полный
   список версий проверенного Windows/Python 3.12 окружения. Для установки нужен доступ
   к индексу Python-пакетов. Уже существующая `.venv` не удаляется.
3. Запустить `START_WEB.cmd` и открыть <http://127.0.0.1:8017/visualization>.
4. Загрузить JSON либо ZIP. Если в архиве несколько источников/сеансов, выбрать
   нужный источник и сеанс. Источники не объединяются в один временной ряд.
5. Для автоматической обработки сеансов открыть
   <http://127.0.0.1:8017/visualization/batch>. Бюджет: 4 попытки, до 90 с на
   источник, 180 с на пакет; загрузка до 512 МиБ. Необработанные сеансы отмечаются
   явно. Кнопка скачивания сохраняет HTML, predictions и manifest в ZIP.

Без веб-сервера:

```powershell
.venv\Scripts\python.exe -m scripts.v9_phase_discovery path\to\input.json
.venv\Scripts\python.exe -m scripts.v9_spatial_visualizer path\to\input.json --output result.html
```

Самодостаточный демонстрационный HTML:
`evidence/release_20261018/synthetic_spatial_demo.html`.
Рядом лежит исходный `synthetic_spatial_demo.json`: 40 синтетических траекторий,
2 оцениваемые логические фазы. Это функциональный пример, не реальная проверка
точности. Для реальной проверки включены прежние predictions, аннотации и
отчёты в `benchmarks/` и `evidence/`; крупные исходные видео в комплект не входят.

## Измеренная точность

Источник: неизменённый `benchmarks/review_closure_20261017/comparison.json`, поле
`after`. Это три знакомые разработчику записи, а не независимый тестовый набор
с телеметрией контроллера или подтверждёнными лампами. Границы сопоставляются
один к одному в абсолютном времени с допуском ±2 с, без подгонки временного
сдвига. K разметки означает число наблюдавшихся меток, не доказательство полного
числа фаз контроллера.

| Запись | K оценки / разметки | Найдено границ / границ разметки | Всего предсказано | MAE найденных, с |
|---|---:|---:|---:|---:|
| `17_2025_2_19_10.json` | 3 / 3 | 15 / 17 | 18 | 0.7093 |
| `19_2025_2_24_16.json` | 2 / 2 | 1 / 8 | 8 | 1.5460 |
| `6_2025_2_14_20.json` | 3 / 2 | 3 / 9 | 15 | 1.4713 |

Для raw HSMM суммарно: 19/34 границы разметки найдены (recall 55.88%),
19/41 предсказаний сопоставлены (precision 46.34%). Для периодического baseline:
17/34 и 17/40 соответственно. MAE только найденных границ не учитывает пропуски
и не должна представляться как ошибка всех переключений. Отдельный новый
операторский набор дал 0/11 границ при том же допуске; его нельзя исключать из
обсуждения качества или объединять с первым набором как независимую lamp truth.
Подробности: `docs/PROJECT_STATUS.md`, раздел 2026-10-15 operator review.

У нового видео Энтузиастов подтверждено происхождение из поставленного DOCX и
совпадение полного SHA256 с ресурсом поставщика. Однако video PTS и JSON millis
ещё не связаны независимым соответствием. Проверенные гипотезы регистрации
отвергнуты; их отрицательные результаты сохранены. Парная точность по этому
видео недоступна. Видимые изменения одной секции ограничены кадровыми интервалами
около 66.7 мс; это не доказательство ошибки алгоритма 1 мс.

Следовательно, **готовность приложения и доказанность точности — разные
результаты**. Максимально теоретически возможная точность не установлена;
называть текущую версию прошедшей итоговую приёмку точности нельзя. По одинаковым
траекториям при отсутствии спроса могут быть совместимы разные состояния ламп;
одного значения «общая точность» без класса режимов, эталона и метрики недостаточно.

## Изменения подготовки комплекта

- Исправлена временная привязка длинных записей: номер строки baseline больше
  не используется как идентификатор фазы. Переименование фаз вместе с шаблонами
  сохраняет результат. Четыре новых независимых примера падали до исправления;
  после исправления проходят вместе с прежним тестом сдвига. Повторной оценки
  реальных записей и заявления о росте их точности не было.
- `pytest.ini` собирает канонические `tests/`, сохраняя архивные оригиналы
  внешнего ревью. Исправлен устаревший тест публичного opt-in: проверяется реальный
  выбор сеанса и передача явного boolean через публичные функции.
- Для двух исторических проверок сохранены 7 точных исходных Git blobs в
  `evidence/release_20261018/historical_sources/`. Старые контрольные суммы,
  планы, результаты и отрицательные выводы не изменены; тесты проверяют код
  соответствующего старого эксперимента, а не запрещают будущие исправления.
- Dockerfile теперь включает `scripts/`, откуда приложение импортирует общий
  визуализатор. `.dockerignore` исключает локальные данные и runtime. Docker
  daemon на этой машине недоступен: реальный контейнер не запускался. Отдельная
  проверка копии только `app/` и `scripts/` подтвердила импорт и HTTP GET для
  `/health`, `/visualization`, `/visualization/batch`.
- В зависимости добавлены `httpx` и `Pillow`, необходимые существующим тестам;
  `INSTALL.cmd` готовит окружение. Версии проверенного окружения сохраняются
  вместе с журналами проверки, без заявления о проверке всех будущих версий.
- Чистый Python 3.12 выявил низкую разрешающую способность Windows
  `time.monotonic` (~15.6 мс) при очень коротком бюджете выборки. Для измерения
  бюджета используется монотонный `perf_counter` с высоким разрешением, а
  достижение deadline считается исчерпанием. Две детерминированные проверки
  точного deadline падали до исправления и проходят после. Исходный полный
  прогон с этой ошибкой и прерванный промежуточный прогон сохранены отдельно.

## Воспроизведение проверки и комплекта

```powershell
.venv\Scripts\python.exe -m pytest -q -p no:cacheprovider
.venv\Scripts\python.exe -m scripts.e2e_smoke
```

Фактические журналы находятся в `evidence/release_20261018/`.
Финальный полный прогон в чистом Python 3.12: **1325 PASS**, 0 FAIL.
До последнего исправления таймера полный прогон в существующем Python 3.14
дал 1323 PASS; после исправления все 10 проверок выборки в нём также проходят.
Компиляция, запуск, сквозной smoke и отдельная обязательная Lenina-регрессия
прошли. Lenina-регрессия проверяет прежние допуски прототипа, а не точность ламп;
её журнал сохраняет и неблагоприятные диагностические ошибки границ.
Первоначальные ошибки сохранены отдельно от повторных успешных проверок.
Синтетическая HTTP-проверка включает загрузку JSON, генерацию HTML, пакетную
обработку и скачивание ZIP. Эти проверки не заменяют таблицу реальных измерений.

После коммита из чистой Git-папки можно создать новый комплект:

```powershell
python -m scripts.build_delivery --output path\to\new_delivery.zip
python -m scripts.build_delivery --verify path\to\new_delivery.zip
```

Существующий ZIP не перезаписывается. `DELIVERY_MANIFEST.json` фиксирует commit,
ветку и SHA256 каждого включённого файла, включая загруженный LFS fixture.
Включаются только отслеживаемые Git файлы; `.git`, локальные медиа, окружения,
runtime и неотслеживаемые файлы не упаковываются. Для повторной проверки самого
ZIP достаточно Python; Git нужен только при сборке нового комплекта.

Main сохранён. Старые результаты не удалялись и не откатывались. Следующая
задача по качеству — проверяемая модель задержки/спроса и независимая оценка
K, состава и временных границ. Фиксированный сдвиг или выбор лучшей из уже
увиденных записей не доказывает решение этой задачи.
