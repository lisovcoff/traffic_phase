# Энтузиастов05.10: связь exposure/PTS с detection timestamp

Источник уже установлен: Инфо.docx, абзац19/rId10, связывает архив
«Ленина-Энтузиастов05.10.24.zip» с https://disk.yandex.ru/i/NwMsnq7xcOIn0A.
Локальное видео побайтно совпадает по полному SHA256 с публичным файлом:
`c574f9204abab0b2bd4dd88425e581da8d335c8e6be0cf4425c0ac7143bfa987`.
Повторное подтверждение даты или ссылки не требуется.

Нужен небольшой fragment исходного экспорта/лога, который связывает:

1. конкретное `detections[].millis` и track ID/JSON member;
2. ID исходной экспозиции и кадр того же автомобиля с рамкой/идентификатором;
3. соответствующий PTS в этом MP4 с рациональным time_base (из MP4:1/90000);
4. источник связи/версию экспортера, определение detection timestamp, clock rate,
   возможные processing/encoding задержки и timestamp uncertainty, если они известны.

Три конкретных lookup examples для `car` даны в
`producer_request_records.json`: точные исходные millis и bbox, без выдуманного
видеовремени. Они относятся только к первым9.3мин шкалы JSON; для проверки drift/
нелинейности нужны также несколько пар из середины и конца записи.

Инфо.docx предупреждает об offline processing. Unix interpretations JSON дают
23.02.2025, camera overlay —05.10.2024; простая замена даты, средний FPS и
совмещение светофорных циклов не определяют связь экспозиций.

Пустой шаблон существующей schema: `frame_clock_links_template.json`.
Если uncertainty/mechanism неизвестны, нужно указать это явно; нулевую ошибку
не предполагать. Запрос подготовлен локально, **не отправлен**.
