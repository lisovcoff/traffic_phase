# Traffic Phase

[English](README.md) · **Русский**

[![Тесты](https://github.com/lisovcoff/traffic_phase/actions/workflows/tests.yml/badge.svg)](https://github.com/lisovcoff/traffic_phase/actions/workflows/tests.yml)

Восстановление фаз светофора по траекториям машин. Приложение анализирует запись
одного перекрёстка, выделяет структуру движения и показывает оценённые сигналы.
Новые наблюдения можно подавать в онлайн-режиме и просматривать в том же плеере.

Код написан на Python, HTTP-интерфейс работает на FastAPI. Подъезды, число фаз
и гипотезы секций определяются из JSON/ZIP. Видео используется только для
проверки результатов и не поступает в алгоритм.

![Онлайн-плеер: машины и оценённые сигналы по реальным траекториям](results/figures/player.png)

## Запуск

Проверенная версия Python — 3.12. На Windows в корне репозитория:

```bat
INSTALL.cmd
START_WEB.cmd
```

Откройте **http://127.0.0.1:8017/visualization**. На Linux или macOS:

```sh
python3.12 -m venv .venv
. .venv/bin/activate
python -m pip install --upgrade "pip>=26.2"
python -m pip install -r requirements-tested-py312.txt
python -m uvicorn app.main:app --host 127.0.0.1 --port 8017
```

Выберите исходный JSON или ZIP с траекториями и нажмите **«Анализировать»**.
После обработки откройте нужную запись: доступны воспроизведение, пауза, скорость,
шкала времени и переход к точному времени. Один архив должен относиться к одному
перекрёстку.

Для онлайн-повтора откройте завершённую модель, перейдите в **«Онлайн»** и выберите
JSONL. Вторую запись можно преобразовать в поток без редактирования исходника:

```sh
python -m scripts.archive_online_packets data/intersection.zip --spool .web_runtime/feed.sqlite3 --output .web_runtime/feed.jsonl
```

Для каждого преобразования указывайте новые выходные пути. Детектор может
отправлять текущие наблюдения на адрес приёма пакетов, показанный в панели.
Формат описан в [контракте API](docs/API.md). Манифест потока и отчёт анализа
не содержат входных траекторий.

Модели, плееры и журналы сохраняются в `logs/intersection_projects/`. Для переноса
готового анализа сохраните эту папку. Знак «?» при запуске означает синхронизацию
или недостаток наблюдений.

## Как это работает

Офлайн-анализ разделяет записи и сеансы, оценивает наблюдаемую геометрию,
группирует разрешённые движения и находит повторяющиеся конфигурации фаз.
В одной модели могут храниться несколько программ работы перекрёстка.

Онлайн использует изученную структуру и обновляет оценку фазы, цвета и времени
по текущим и предыдущим наблюдениям. Учитываются трогание первой машины,
проезды, торможение и ожидание в очереди. Конкурирующие гипотезы длительности
позволяют отслеживать новый период или разовое продление зелёного.
Отсутствие машин само по себе не доказывает красный сигнал.

Плеер показывает фактическую локальную историю офлайн-анализа или исходные
выданные онлайн-оценки. Журнал пакетов и контрольные точки позволяют продолжить
поток после перезапуска. Старые журналы v7 совместимы; новые модели с выученной
геометрией очередей используют v8.

## Результаты

В проверке ниже — **восемь контролируемых сценариев SUMO**. Случайные
последовательности обучения и проверочного потока различаются. Все основные
светофоры и цвета оцениваются посекундно; UNKNOWN считается ошибкой.
Одна светофоро-секунда — один светофор, проверенный в течение одной секунды.

![Точность по сценариям и полнота распознавания каждого цвета: v7 и v8](results/figures/replay_evaluation.png)

| Показатель | v7 | v8 |
|---|---:|---:|
| Точность всех цветов, 22 010 светофоро-секунд | 89,57% | **93,51%** |
| Полнота зелёного, 7 966 светофоро-секунд | 96,77% | **99,37%** |
| Полнота красного, 12 969 светофоро-секунд | 91,10% | **94,66%** |
| Полнота жёлтого, 645 светофоро-секунд | 3,72% | **22,64%** |
| Полнота красно-жёлтого, 430 светофоро-секунд | 38,60% | **56,51%** |
| Ложный зелёный, светофоро-секунды | 920 | **666** |

Короткие цвета остаются самым слабым местом. В общей метрике преобладают
красный и зелёный, поэтому 93,51% нельзя переносить на каждый цвет отдельно.
В плеере жёлтый и красно-жёлтый помечены как **оценка времени перехода**:
момент переключения вычислен косвенно, лампа непосредственно не наблюдалась.
В ходе аудита декодер и его выданные цвета сохранены без подстройки под уже
известные проверочные сценарии.

Остаются два ухудшения относительно v7: ложный зелёный в одном сценарии смены
периода и красно-жёлтый на Т-образном перекрёстке. Строгий критерий отсутствия
ухудшений не пройден. Посценарные результаты опубликованы в
[полном отчёте](results/causal_v8.md).

Проверка по реальному видео имеет более узкое покрытие:

| Проверка | Результат | Что именно проверялось |
|---|---:|---|
| Размеченные интервалы зелёного/жёлтого видимого N | 148/153 = **96,73%** | Известное окно, условная привязка часов |
| Копия входа с продлением зелёного на 12с | 153/165 = **92,73%** | Контрфактический пример, не реальный проезд спецтранспорта |
| Отдельное включение зелёного | Ошибка **1,42с**, ранее 3,42с | Расстояние до условного диапазона привязки часов |

Обработаны шесть реальных архивов трёх перекрёстков. Полного независимого эталона
ламп для всех архивов нет. Эти измерения не доказывают точность 95% на всех
шести архивах и не подтверждают физическое оборудование.

Таблицы и график собраны через pandas из сохранённых протоколов измерений.
В репозиторий включены только результаты; скрипт построения остаётся локальным.

## Разработка

```sh
python -m compileall -q app scripts tests
python -m pytest -q
python -m scripts.e2e_smoke
```

Крупный регрессионный пример хранится через Git LFS: после клонирования выполните
`git lfs pull`. Проверки частных записей пропускаются в чистом клоне.
Тесты покрывают чтение данных, алгоритм, временные границы, API, восстановление
журнала и плеер. Дополнительные проверки SUMO и браузера описаны в
[руководстве](GUIDE.ru.md).

| Папка | Содержимое |
|---|---|
| `app/core/`, `app/experimental/` | Алгоритм, восстановление фаз и исследовательские реализации |
| `app/api/`, `app/static/` | HTTP-интерфейс и ресурсы плеера |
| `scripts/` | CLI, симуляторы и проверочные прогоны |
| `tests/` | Модульные, регрессионные и API-тесты |
| `docs/`, `results/` | Архитектура, форматы данных, измерения и аудит |

Исходные записи, готовые плееры, кадры, логи и исследовательские прогоны
сохраняются локально и исключены из Git. `config/` нужен отдельным прежним
диагностическим инструментам; автоматический анализ не выбирает именной
профиль перекрёстка.
