# Руководство Traffic Phase

[English](GUIDE.md) · **Русский**

## Офлайн и сохранённые проекты

На Windows выполните `INSTALL.cmd`, затем `START_WEB.cmd`. Откройте
http://127.0.0.1:8017/visualization. `START_WEB.cmd --check` проверяет установку.

Загрузите исходный JSON/ZIP одного перекрёстка. Дождитесь READY или PARTIAL;
при частичном результате посмотрите ошибки источников. Выберите запись и время.
Отчёт анализа, JSON модели и манифест потока не заменяют исходные траектории.
Прерванный офлайн-анализ пока не возобновляется автоматически.

Модели, исходные записи, плееры и журналы находятся в
`logs/intersection_projects/<model_id>/`. Для переноса анализа сохраняйте всю
папку. Скачанный JSON модели не является полным экспортом.

## Онлайн-пакеты

Откройте готовую модель, выберите **«Онлайн»** и используйте адрес приёма из
панели. Другой вариант - хронологический JSONL: один пакет в строке.
Конечный повтор заканчивается последним пакетом; для продолжения нужны новые
наблюдения.

```json
{
  "sequence": 0,
  "timestamp_ms": 1800000000000,
  "vehicles": [{
    "id": "car-1",
    "zone_in": "N",
    "detections": [{
      "millis": 1800000000000,
      "centroid_x": 0.5,
      "centroid_y": 0.2,
      "zone": "N"
    }]
  }]
}
```

Время задаётся в миллисекундах Unix. Разрешены только наблюдения, доступные
к `timestamp_ms`; будущий выезд (`zone_out`) передавать нельзя. В детекциях
также допустимы `speed`, `lat` и `lng`. Система координат должна совпадать
с офлайн-записью. Типы, ограничения и адреса API доступны на **/docs** сервера.

Одинаковый повтор пакета не меняет ответ. Конфликт последовательности и будущие
детекции отклоняются. Пустой `vehicles` - сигнал присутствия источника, а не
свидетельство красного. «?» при запуске означает синхронизацию или недостаток
данных. История отделена от прямого эфира и сохраняется после перезапуска.

Подъезды, K и секции фиксируются офлайн-моделью. Онлайн обновляет состояние и
гипотезы длительности. По одному необычному интервалу нельзя узнать его причину,
например проезд спецтранспорта.

## Обновление старой модели

Повторно проанализируйте её исходный офлайн-архив или создайте отдельную копию:

```sh
python -m scripts.enrich_intersection_model logs/intersection_projects/OLD_ID --output logs/intersection_projects/NEW_32_HEX_ID
```

Используйте новый идентификатор из 32 шестнадцатеричных символов. Старые модели
и журналы сохраняются: история v7 остаётся на v7; новые модели с обученной
геометрией очередей используют v8.

## Проверки и упаковка исходников

```sh
python -m pip install -r requirements-dev.txt
python -m pytest -q
python -m scripts.verify_delivery --project MODEL_ID --packets real_packets.jsonl --output new_check.json
python -m scripts.build_delivery --output new_source.zip
```

HTTP-проверке нужны работающий сервер, готовая модель и пакеты. Она создаёт
отдельный поток и проверяет плееры, дубли, будущие детекции и перемотку.
Точность ламп она не измеряет. Упаковка требует чистое закоммиченное дерево,
включает отслеживаемые файлы и проверяет хеши; указывайте новое имя архива.

Для браузерной проверки нужны `scripts.qa_intersection_delivery`, Playwright
и установленный Edge. Для независимой симуляции нужен `eclipse-sumo==1.28.0`:

```sh
python -m scripts.validate_causal_v8 --sumo-home PATH_TO_SUMO --output .web_runtime/new_validation --require-acceptance
```

Строгий критерий точности пока не пройден; `--require-acceptance` завершится
с кодом 2. [Измерения и ограничения](results/README.ru.md) отделены от
проверок работоспособности.
