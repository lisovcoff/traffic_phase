# Запуск и проверка Traffic Phase перед сдачей

[English](DELIVERY.md) · **Русский**

В поставку входят приложение на Python, исходники, тесты и компактные результаты
проверок. Это работающий исследовательский прототип. Точность физических цветов
на всех шести архивах независимо не подтверждена. Новые офлайн-модели с геометрией
очередей используют встроенный v8. Старые модели без геометрии и журналы v7
продолжают работать со своей исходной версией.

## Запуск

Нужен Python 3.12. На Windows один раз выполните `INSTALL.cmd`, затем
`START_WEB.cmd`. Откройте **http://127.0.0.1:8017/visualization**.
Если сервер уже работает, второй на том же порту не запустится. Для проверки
окружения: `START_WEB.cmd --check`. Новая `.venv` имеет приоритет над старым
локальным окружением разработки.

1. Прикрепите исходный JSON или ZIP одного перекрёстка и нажмите
   **Анализировать**. Дождитесь результата; при PARTIAL посмотрите ошибки источников.
2. Выберите запись. Проверьте машины, предполагаемые светофоры и секции,
   воспроизведение, паузу, скорость, перемотку и выбор времени.
3. Нажмите **Онлайн**. Выберите секундный JSONL в поле онлайн-потока или
   отправляйте текущие пакеты на показанный POST-адрес. Формат — в
   [описании API](docs/API.md). `feed_manifest.json` не содержит машин и не
   заменяет поток. Офлайн-поле принимает исходные JSON/ZIP, не JSONL.
4. Проверьте переход к прошлому времени и возврат к текущему пакету. После
   обновления страницы модель и принятая история восстанавливаются. Конец файла
   означает завершение конечного повтора; для продолжения нужны новые пакеты.

Модели, сеансы, плееры и журнал находятся в `logs/intersection_projects/`.
Они не входят в архив исходников. Для переноса существующего анализа сохраните
эту папку: скачанный model JSON не является полным экспортом проекта.
На чистом компьютере загрузите исходный архив и выполните анализ заново.

## Проверка

Второй JSON/ZIP можно преобразовать в поток без ручного составления пакетов:

```sh
python -m scripts.archive_online_packets intersection.zip --spool .web_runtime/feed.sqlite3 --output .web_runtime/real_packets.jsonl
```

Полученный JSONL выберите в онлайн-поле. Каждый раз указывайте новые пути
выходных файлов. Промежуточная SQLite сохраняется локально, исходный архив
не меняется.

```sh
python -m pytest -q
python -m scripts.verify_delivery --project MODEL_ID --packets real_packets.jsonl --output new_check.json
python -m scripts.build_delivery --verify traffic_phase_source.zip
```

HTTP-проверка требует работающий сервер и готовую модель. Она создаёт отдельный
сохранённый проверочный поток: проверяет ответы плееров, приём пакетов, защиту
от дублей/конфликтов/будущих детекций и точность перемотки принятой истории.
Это проверка работоспособности, не измерение точности цветов и не визуальный осмотр.

## Как представлять результат

Показывайте автоматическое определение наблюдаемых подъездов, K и гипотез секций,
общий офлайн/онлайн-интерфейс, машины и журнал. Отдельно показывайте
[измерения точности](results/README.md) и [проверку поставки](results/delivery_readiness.json).

Не переносите экспериментальные 95% на приложение и все реальные архивы:
это результат отдельных известных сценариев SUMO. Оценка видимого N относится
только к размеченным зелёному/жёлтому и условной привязке часов.
Последняя [проверка v8](results/causal_v8.md): 93,51% против 89,57% на восьми
независимых сценариях; задержка известного реального зелёного — 1,42с вместо
3,42с. Строгая приёмка не пройдена: ложный зелёный в одном сценарии смены периода
и красно-жёлтый на Т‑образном перекрёстке ухудшились. Привязка JSON/видео Энтузиастов
и полная разметка всех голов не подтверждены. Текущая приёмка описана в
[PROJECT_STATUS.md](docs/PROJECT_STATUS.md). Прохождение тестов и целостность
архива не означают безошибочное определение всех сигналов.

Старую сохранённую модель можно обновить без перезаписи исходника и журналов:

```sh
python -m scripts.enrich_intersection_model logs/intersection_projects/OLD_ID --output logs/intersection_projects/NEW_32_HEX_ID
```

Укажите новый идентификатор из 32 шестнадцатеричных символов. Другой вариант —
повторно проанализировать исходный архив: геометрия очередей теперь обучается
автоматически. Видео, ручная схема и онлайн-запись для обучения не нужны.
При запуске потока «?» с подписью «синхронизация по движению» означает недостаток
накопленных признаков. Пустой поток сам по себе не определяет цвет светофора.
